Overview

Duende supports importing other source files as modules. Each .du file is a module, and the module name is the file path from the project root without extension, using dots as separators. For example, examples/modules/testModule.du has the module name modules.testModule.

Basic import

import modules.testModule

int main() do
    print(testModule.add(1,2))
end

By default, importing a module provides a short alias equal to the last path segment (here testModule). Use that to qualify functions and types from the module.

Selective import

import modules.otherModule { subtract }

int main() do
    print(subtract(2,4))
end

You can import a subset of symbols. Internally the compiler creates aliases so names appear directly in the current file.

Aliases

import modules.testModule as TM
import modules.otherModule { subtract as minus }

int main() do
    print(TM.add(1,2))
    print(minus(2,4))
end

Relative imports

Inside a module the compiler resolves bare names relative to the current module's parent. For example from modules/testModule.du you can write:

import otherModule

This is resolved to modules.otherModule if such module exists.

Re-exports and visibility

public import modules.testModule
private import modules.otherModule { subtract }

public import re-exports a module's public API from the current module. private import keeps it internal (the default).

Wildcards

Writing import some.module.* expands to import all exported symbols from that module (resolved statically at compile time).

Notes

  • Imports are resolved relative to the project root and the current module.
  • Circular imports are supported; the compiler builds a module graph and generates each module once.
  • Standard library is reserved under the std prefix.
  • Math functions require import std.math in each module that uses them.
  • Built-in providers: the Duende compiler embeds a small set of provider manifests (for example: terminal, std.csv, std.json) so these modules are available out of the box. If a provider declares external dependencies (e.g. a dub package), the compiler will automatically build your program via dub when needed — no manual setup required beyond having a D toolchain and dub installed.
  • Additional providers: you can still add your own by placing a duende_packages folder next to the duende executable with provider manifests. The compiler will load these in addition to the built-ins.
