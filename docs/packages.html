Packages

Home Imports

Duende can import modules that are provided by external D libraries (or internal helpers) without modifying the compiler for each module. This page explains how to add such modules via data-driven manifests and where Duende looks for them.

Overview

  • Packages are folders containing a duende-package.toml manifest.
  • Manifests declare one or more Duende module names and how they map to D: required D imports, symbol aliases, optional helper .d files, and optional dub dependencies.
  • When your Duende module imports a name not found in your project, the compiler consults these manifests to satisfy it.

Discovery location

Duende only looks for packages in one place:

  1. duende_packages/ next to the duende executable.

Each direct child directory is probed for a duende-package.toml manifest. This keeps distribution self-contained and avoids relying on user/system environment.

Manifest format

The manifest is a minimal TOML-like file parsed by the compiler. Supported fields:

name = "duende-std-csv"
version = "0.1.0"

[modules.std.csv]
imports = ["std.csv"]
aliases = { }
helpers = []

# Optional: dub dependencies (resolved only when providers are used)
[dub]
dependencies = { "toml-d" = "~>0.4.0" }
  • modules.<duende.module.name> declares one provided module.
  • imports: array of D modules to import in generated code.
  • aliases: inline table mapping friendly names to module.symbol (e.g., { println = "std.stdio.writeln" }).
  • helpers: array of additional D source files to compile alongside generated code.
  • [dub].dependencies (optional): name→version map to include when building via dub.

Using a package

  1. Place a package directory (with duende-package.toml) under one of the discovery roots.
  2. Import the declared module name in your Duende code, e.g. import std.csv.
  3. Compile normally. If any used provider declares dub deps, Duende will synthesize a temporary dub project and build with dub. Otherwise, it compiles directly with dmd.

Example: std.csv

This repo includes a minimal provider for D's std.csv bundled with the compiler:

examples/
  std_csv_example.du
duende_packages/
  stdcsv/
    duende-package.toml  # provides modules.std.csv = { imports = ["std.csv"] }

And the Duende code:

import std.csv

let string text = "name,age\nAlice,30\nBob,25\n"
var int count = 0
for rec in csvReader(text) do
  if count == 1 do
    var int i = 0
    for field in rec do
      if i < 2 do
        print(field)
      end
      i = i + 1
    end
  end
  count = count + 1
end

Run with:

$ ./duende examples/std_csv_example.du -r
Alice
30

Example: std.encoding

The repo bundles a provider for encoding helpers:

duende_packages/
  stdencoding/
    duende-package.toml   # provides modules.std.encoding with helpers
    duende_encoding.d     # implementation

Usage:

import std.encoding
let string s = "Hello"
let string b64 = base64Encode(utf8Encode(s))
print(b64)

Example: vibe_d

The repo includes a comprehensive vibe.d integration provider:

duende_packages/
  vibed/
    duende-package.toml   # provides modules.vibe_d with full web framework
    duende_vibed.d        # wrapper implementation

The vibe_d package provides complete web development capabilities including:

  • HTTP/HTTPS server and client
  • WebSocket server and client
  • SSL/TLS context management
  • Async operations and timers
  • Database access and connection pooling
  • Logging system
  • File system operations
  • Process management

Usage example:

import vibe_d

// Start HTTP server
let string serverId = startServer(8080, false)

// Create HTTP client
let string clientId = createHttpClient()
let string response = httpGet(clientId, "http://example.com/api")

// WebSocket server
let string wsId = createWebSocketServer(9001, "/ws")

// Async file operations
let bool success = writeFileAsync("data.txt", "Hello World")
let string content = readFileAsync("data.txt")

// Logging
let string logger = createLogger("MyApp", 2)
logInfo("Application started")

// Timers
let string timerId = createTimer(1000, true)

Aliases and helpers

Aliases provide ergonomic names for D symbols. For example:

aliases = { println = "std.stdio.writeln" }

Then in Duende:

import mylib.util
println("hello")

Helpers are paths to additional D source files shipped with the provider; they are compiled together with generated code.

Edge cases and tips

  • std.* imports: If you import std.* without a provider, Duende will not error and may handle some features internally (e.g., std.math helpers). To map arbitrary std.* imports to D, add providers.
  • Provider precedence: If multiple packages declare the same Duende module inside duende_packages/, the first directory entry discovered wins.
  • Dub dependencies: If any used provider declares dub deps, Duende switches to a temporary dub build. This requires network access for missing packages and the dub tool installed.
  • Helpers paths: Relative paths are resolved relative to the manifest directory; absolute paths are respected.
  • Selective imports: You can still use selective or wildcard imports on your own project modules. Provider-backed modules don’t generate a D import for the Duende module name, only the declared D imports and aliases.

Checklist for adding a new package

  1. Create a folder under one discovery root.
  2. Add duende-package.toml with name, version, and one or more [modules.<name>] entries.
  3. Fill imports, aliases, and optional helpers. Add [dub].dependencies only if needed.
  4. Compile a small example; set DUENDE_PATH to your provider root if it’s not under your project.

Bundled providers

  • std.csv — thin mapping to D's std.csv.
  • std.encoding — UTF-8/16, Base64, Hex helpers.
  • std.xml — XML parsing/writing via dxml.
  • std.net, std.process, std.db — see respective docs.
  • std.hash / std.digest — hashing & checksums (MD5, CRC32/64, SHA-1/2, MurmurHash3). See Hashing.
  • vibe_d — complete web framework integration providing HTTP server/client, WebSockets, async operations, SSL/TLS, database access, logging, timers, filesystem, and process management via vibe.d.
