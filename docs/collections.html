Available methods

  • Lists
    • add(x: T)
    • slice(start: int, end: int) -> list<T>
    • length property and length() method
    • empty property
    • first / last properties, each Maybe<T>
    • xs[i] = value replaces one element
    • sort() (in-place, lexicographic)
    • join(sep: string) -> string
  • Dictionaries
    • dict<K, V> keeps the key type and the value type
    • has(key: K) -> bool
    • get(key: K) -> Maybe<V>
    • d[key] = value inserts or replaces one entry
    • length property and empty property
    • keys -> list<K>, values -> list<V>
    • items() yields entries with .key and .value

Dictionary types

dict<K, V> is the dictionary type. Keys and values stay those types through the literal, lookup, insertion, keys, values, and items(). V may be a struct, a frame, or another collection. A value that is not already V is written with an explicit conversion such as string(8080). An int may be stored in a float slot. Mixed key types or mixed value types are rejected.

auto infers K and V from a non-empty literal when every key has one known type and every value has one known type. An empty {} takes K and V from the declaration. let auto d = {} has nothing to infer, so it is rejected.

A bare dict means dict<string, string>. That is the old string dictionary. It does not turn numbers or bools into text. File metadata, process environment, and XML attributes are string dictionaries.

Missing elements

first and last are Maybe<T>. An empty list is None. A list that contains -1 or "-1" is Some of that value. Read it with ? else.

xs[i] and d[key] require the element to exist. A missing index or key aborts the program. has(key) is the check before indexing. get(key) is the absence check: it returns Maybe<V>, so a stored 0 or -1 is different from a missing key. for x in dict yields values.

Bindings

let and var control the name, not the collection. A let list or dict cannot be assigned a new collection. add, sort, xs[i] = value, and d[key] = value still update the existing collection, whether the name was written let list<int> or let auto. sort is in place, so another name for that list sees the new order. add can allocate a larger array and leave older names pointing at the previous elements. var can also replace the collection with another one.

Lists

var list<int> numbers = [1, 2, 3, 4, 5]
numbers.add(6)
let int first = numbers[0]
print(numbers.length)
print(numbers.empty)
let list<int> slice = numbers.slice(1, 4)
let int numbers_first = numbers.first ? else 0
let int numbers_last = numbers.last ? else 0
// In-place sort (lexicographic)
var list<string> names = ["bob", "alice", "carol"]
names.sort()
print(names.first ? else "") // "alice"
print(names.last ? else "")  // "carol"

let list<int> empty = []
print(empty.first ? else "absent") // "absent"
let list<int> neg = [-1]
print(neg.first ? else 0) // -1

Dictionaries

var dict<string, int> config = {"port": 8080}
if config.has("port") do
    let int port = config["port"]
end
config["extra"] = 1
let int missing = config.get("host") ? else 0

let dict<string, string> text = {"port": string(8080)}
let auto inferred = {"n": 7}

print(config.length)
print(config.empty)
let list<string> keys = text.keys
let list<string> values = text.values

Empty collections

let list<string> xs = []
let dict<string, int> d = {}
let dict text = {} // dict<string, string>
