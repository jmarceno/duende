Built-in types

  • int — 64-bit integer
  • float — double-precision
  • string
  • bool
  • bytes — byte array
  • list<T> — dynamic array (must specify element type)
  • dict — associative array
  • auto — inferred type of the initializer
  • User-defined: struct, frame, enum, and protocol

Type annotations

let int a = 1
let float b = 3.5
let string s = "text"
let list<int> xs = [1, 2, 3]
let list<list<int>> grid = [[1, 2], [3]]
let dict d = {"k": 1}
let auto n = 42 // inferred as int
let bool ok = 1 < 2

int

int is a signed 64-bit two's complement integer. Literals must be in the closed range -9223372036854775808 .. 9223372036854775807. A literal outside that range is rejected. The minimum value is written with a leading minus; the positive magnitude 9223372036854775808 is not itself a valid int.

Arithmetic wraps modulo 264. 9223372036854775807 + 1 is -9223372036854775808. int converts to float implicitly; values beyond the 53-bit mantissa are not all exact. int(x) truncates a float toward zero (int(3.9) is 3, int(-3.9) is -3). A float that is not a finite value in range becomes 0.

Comparisons and logic

==, !=, <, >, <=, >=, &&, ||, and ! produce bool. Arithmetic operators produce int or float. A bool result can be stored in a bool variable.

auto

auto takes the type of its initializer when that type is known, and later uses are checked as that type. let auto n = 42 is an int. let auto ok = 1 < 2 is a bool. If the initializer's type cannot be resolved (for example a call into an imported library), the binding stays unresolved and is not treated as a concrete type.

Nested generics

Generic arguments are kept at every level: parameters, returns, fields, and expressions. list<list<int>> is a list of int lists, so indexing once yields list<int> and indexing again yields int. The same rules apply to Result and Maybe payloads such as Result<list<int>>. An empty list literal takes its element type from the declared type: let list<list<int>> rows = [].

Generics-like containers

Containers use explicit element types, e.g., list<int>, list<string>. Empty list literals require context: let list<string> xs = []. Algebraic results use constructor names (see Result & Maybe).

Result and Maybe

These are sum types with constructors Ok/Error and Some/None. Use the ? else operator to provide a fallback. See the dedicated page: Result & Maybe.

Type casting

Use function-like syntax to convert between core types:

let int a = int(3.99)      // 3
let float b = float("2.5") // 2.5
let string s = string(42)  // "42"
// Works with variables and expressions too:
let int n = int("10") + int(2.7) // 12

Casting relies on conversion semantics similar to D's std.conv.to. Converting malformed strings to numbers may raise a runtime error.
