let vs var

let freezes the name. var allows a later assignment to that same name. This is about the binding, not about whether the value's contents can change.

  • let — the name cannot be assigned again. Annotated and inferred forms follow the same rule: let int x = 1 and let auto x = 1.
  • var — the name can be assigned again: var int y = 1 and var auto y = 1.
  • Parameters are reassignable locals. Reassigning a parameter does not change the caller's binding.
  • for and for-in names, and names bound in a match, are let bindings.
  • Lists, dicts, and bytes are shared values. let list<int> xs = [1] cannot be rebound, but xs.add(2), xs[0] = 2, and xs.sort() update that value. let dict<string, int> d = {"a": 1} cannot be rebound, but d["a"] = 2 and d["b"] = 3 update that dictionary. An alias created before sort sees the sorted elements. add may detach a list from older aliases when the array grows.
  • Assigning to a let name is rejected. So is calling a frame method that writes fields, or writing a frame field, when the receiver name is let.
let int x = 42
var int y = 13
y = y + 1
print(x + y)

let list<string> names = ["b", "a"]
let list<string> same = names
same.sort()
print(names.first ? else "") // "a"

A let whose value is not shared (int, float, string, bool, enum, struct, and other value types) is stored so the generated program cannot assign it again. A runtime initializer for that kind of global runs at startup, in source order, when no earlier statement or deferred var has to run first. If one does, the initializer stays in source order among the top-level statements and the compiler still rejects a later assignment. Lists, dicts, bytes, frames, and bindings whose type is still unresolved keep mutable storage because their contents, or the D representation, are not a frozen value. let still forbids rebinding those names.

The same type and mutability checks apply inside elif branches, deferred calls, and expressions passed to builtins such as print. A frame method that changes fields in a local initializer, match guard, or nested block is also a mutating method.

Global Variables

Variables declared outside of functions, frames, or structs are treated as global variables. They are accessible from any function, frame, or struct within the same module.

Global Variable Declaration

  • Global variables are declared at the module level (outside any function)
  • They can be either immutable (let) or mutable (var)
  • Global variables are initialized when the program starts
  • They maintain their values throughout the program execution
// Global constants
let float pi = 3.141592653589793
let int maxUsers = 1000

// Global mutable state
var int requestCount = 0
var string lastUser = ""

void processRequest(string username) do
    requestCount = requestCount + 1
    lastUser = username
    print("Request #" + requestCount + " from " + username)
end

int main() do
    print("Pi value: " + pi)        // Access global constant
    print("Max users: " + maxUsers) // Access global constant
    
    processRequest("alice")         // Modifies global state
    processRequest("bob")           // Modifies global state
    
    print("Total requests: " + requestCount) // Access modified global
    print("Last user: " + lastUser)         // Access modified global
end

Scope Resolution

  • Local variables can shadow global variables within their scope
  • When a local variable has the same name as a global, the local takes precedence
  • Global variables cannot be re-declared within local scopes
let string globalName = "Global"

void testScope() do
    let string globalName = "Local"  // Shadows global variable
    print(globalName)                // Prints "Local"
end

int main() do
    print(globalName)  // Prints "Global"
    testScope()        // Prints "Local"
    print(globalName)  // Prints "Global" again
end

Local Variables

Variables declared inside functions, frames, or structs are local to that scope.

Struct and frame rules

  • Struct fields are immutable. Methods return new values rather than modifying in place. Declare a struct with let. var is rejected.
  • A frame name declared with let can be read. Methods that write fields, and field assignments, require a var receiver. let does not follow the value through a parameter: the parameter is a new reassignable binding and may update the same frame.
